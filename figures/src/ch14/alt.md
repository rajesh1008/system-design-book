# ch14 alt text (one line per figure; copied into 03-figures/alt.md for the build)
fig-14-1: Two horizontal bars for one model call of 6,217 input tokens and 173 output tokens on a self-hosted engine at a batch of 16, the cold prompt spending 0.53 seconds in prefill and the warm prompt with 78% cached spending 0.12 seconds, with decode taking about 3.9 seconds in both, so totals are 4.47 and 4.06 seconds.
fig-14-2: A sequence diagram of continuous batching in which the scheduler runs one decode step for 64 calls, a finished call leaves and frees its memory blocks, and a waiting call joins at the next step with its prompt prefilled in 512-token chunks beside the running calls.
fig-14-3: A diagram of paged key-value memory in which two calls map their blocks through a block table to free physical blocks, both pointing at one shared prefix held once, with a note that 60 gigabytes holds 30 calls contiguously, 85 paged, and 149 with the shared prefix.
fig-14-4: Two rows of prompt segments, the pilot's with tools, then a clock and the itinerary marked as changing, then instructions, policy, and history, reading 9% cache hit, and the stable-first row with tools, instructions, policy, and examples first, a cache mark, then the itinerary and history, reading 78%.
fig-14-5: A grouped bar chart of the share of input tokens read from cache for the provider API and two open engines, the pilot layout at 9% on all three and the stable-first layout at 78% on the API and 82% and 83% on the engines.
fig-14-6: A sequence diagram of speculative decoding in which a small draft model guesses four tokens, the large target model checks all four in one pass, keeps three, rejects the fourth, and supplies its own token, so four tokens come from one large pass.
fig-14-7: Four curves of speed-up against the share of draft tokens accepted for batch sizes 1, 8, 64, and 128, with a dashed line at no speed-up, showing large gains at batch 1 and a loss below the line at 40% acceptance for batches of 64 and 128.
fig-14-8: A diagram of disaggregated serving in which a router sends calls to a prefill pool, the key-value cache moves over the network to a decode pool that writes tokens to the agent loop, beside the alternative of one pool doing both phases, with a note that the split pays for long prompts with short outputs.
fig-14-9: A table of five serving engines and orchestration layers as of November 2026, vLLM, SGLang, TensorRT-LLM, Dynamo, and llm-d, with how each reuses prompt prefixes, whether each can split prefill from decode, and the release current when checked.
fig-14-10: A log-log chart of dollars per task against tasks a month, with a flat line for the frontier API at about seven cents a task and two falling lines for self-hosted fleets of 2 and 16 graphics processing units that cross the API line at about 162,000 and 682,000 tasks a month, far right of the April 2026 volume of 20,100.
fig-14-11: The self-host decision table from April 28, 2026, keeping the API for frontier steps at $1,573 a month and for small steps at $52, and deferring a two-GPU small-model fleet at $12,672 that would be 1.2% busy and a sixteen-GPU frontier-class fleet at $53,376, with a revisit trigger of 100,000 tasks a month.
