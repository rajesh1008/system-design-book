fig-22-2: A four-row table of memory types: short-term holds this conversation in a session store that ends with the session; trip holds one itinerary's requests in the governed store until the trip ends; standing holds confirmed preferences for 180 days with versions; episodic holds what happened before in the trail and cases, read by the desk.

fig-22-4: A sequence among the loop, the store, and the trail: the loop sends a draft with a source, the store takes the tenant and runs its checks and head comparison, writes a line to the trail, and returns the record; a second draft with no source is refused, shown as a red arrow to the trail.
fig-22-5: A table of four roles against preferences, health and consent, and history: the agent loop reads preferences only; the agent desk and the privacy office read all three; analytics reads none; a note says the tenant comes from the session token.
fig-22-6: A state diagram: a written record becomes head; a newer observation moves it to superseded; a stale head or an older observation goes to refused; erasure moves either head or superseded to deleted with a tombstone, which ends the record.
fig-22-7: A top-to-bottom flow from an erasure request to her four records, then along an emphasized derived-from arrow to two derived records, one on a companion; all six feed six tombstones, which, with a restored backup, feed a gate that replays tombstones before reads.
fig-22-8: A top-to-bottom flow from a proposal and its grounds to a grounds check; a red dashed arrow marked cites memory goes to the desk, which checks the record, and an emphasized arrow marked records only goes to the control plane, which issues a permission record.
fig-22-9: Two paths from one request for an aisle on the Tokyo flight: a red path to a pilot note with no scope that gave an aisle on three of three later trips, and an emphasized path to a trip memory for Tokyo only, so later trips ask.
