fig-33-1: A top-to-bottom diagram: the attacker feeds four entry points, chat and letters, tool results, tool text, and memory; all four lead into the agent loop, and the agent loop reaches the records only through the gateway.
fig-33-2: A five-row table with columns plane, surface, and control: on the action plane, chat, letters, and voicemail go through the input contract, and tool results are untagged, highlighted as a gap; on the knowledge plane, notices and memory go through fields and the write gate; on the control plane, tool descriptions go through review and the hash; on the trail, text read later is kept as digests only.
fig-33-3: A top-to-bottom diagram of the lethal trifecta for one itinerary: untrusted input, A, from chat and tool results, and private data, B, from booking_read and doc_intake, meet in one session; the session leads to the gateway, which closes the outbound path, C, with the egress list and sends every state change, also C, through policy with a permit.
fig-33-4: A sequence diagram with a supplier, the gateway, and the agent: the supplier submits a tool description and the gateway rejects it; the supplier changes the text; when the agent calls the tool, the gateway finds that the hash differs and refuses the call.
fig-33-5: A top-to-bottom diagram of five exfiltration paths out of the session: code posting to a host and data in a URL both meet the egress allow-list of names over HTTPS; an image or link in a reply meets the reply filter, which allows the company's own pages only; free text or a log in a tool argument and a notification with a custom template both meet the gateway's schema and registry.
fig-33-6: A sequence diagram with the customer, the agent, and the session binding: the customer asks to refund another booking and the agent calls refund_ticket; the binding finds the booking is not this session's, writes both identities to the trail, and refuses; the agent tells the customer it can act on this booking only.
fig-33-7: A five-row table with columns plane, control, and guarantee: action, the input contract and reply filter, fields in and text out; control, policy and session binding, exact permits; gateway, egress and the description hash, no way out; knowledge, the memory write gate, no note becomes a rule; trail, both identities, replayable.
fig-33-8: Stacked horizontal bars for the battery of June 16, 2026, one per attack class, on an axis of attacks out of 61 with none reaching an effect: direct 8, with 2 stopped in context, 5 refused, and 1 proposal; indirect 16, with 12 stopped at entry, 2 refused, and 2 proposals; poisoning 10, with 7 at entry and 3 refused; memory 8, with 6 at entry, 1 refused, and 1 proposal; exfiltration 10, all refused; deputy 9, all refused.
fig-33-9: A top-to-bottom diagram: an injected promise in session 1 passes the memory write gate into the memory store; in session 2 the agent proposes a refund from it, and policy refuses because memory is not authority.
fig-33-10: A five-row table with columns topic, this chapter, and the sibling book: red teaming, a battery per release here and adaptive campaigns there; detection, a signal here and classifier design there; identity, delegated identity here and token exchange there; supply chain, review and the hash here and signing there; response, trail inputs here and forensics and law there.
